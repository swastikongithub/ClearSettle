ClearSettle design concepts

Three static pages that show the proposed visual direction. They are design references, not the application, and are not connected to a backend. The written proposal, approved on 19 October 2026, is docs/design/clearsettle_frontend_design_proposal.md.

  • Period overview

    The application shell and the first screen of a period.

    • The settlement chain: orders to posted journals, with each link's open items above it.
    • Needs attention, ordered by risk and then age; every item says what its button does.
    • Amounts in Indian digit grouping with the currency code (decision 3).

  • Reconciliation results

    One run's differences, with the selected payment's trace from order to journal.

    • Gross compared with gross; the fee and tax reported on the line shown beside the comparison.
    • Both original amounts and the unexplained difference, never a corrected value.
    • A partially imported input announced above the results that depend on it.

  • Sign-in, confirmation and data states

    Pages that exist in some form today, redesigned.

    • The second sign-in after enrolling an authenticator, explained rather than shown as an error.
    • A sensitive action: verify it is you, review, confirm once; refused and expired confirmations.
    • Loading, empty, error and partial states.

Viewing them

Open this file directly in a browser; no build or server is needed. The pages load IBM Plex from Google Fonts and fall back to a system font when offline (the application would serve its fonts itself).

To see the tablet and phone layouts, narrow the window below 1100 px and 960 px, or use the browser's device mode at 390 px wide.
